# Anti-confusion rules (permanent)

## 1. One question test

Before trusting any doc/plan/agent output, ask:

> Is this listed ACTIVE_CANONICAL in the Master Document Register with a Drive link and SHA-256?

If no → it is draft, history, or noise.

## 2. One write path

Official changes only via:

**HUMAN-SOP** → Drive masters → Register → Notion projection → Obsidian pointer → Linear close  

## 3. One roadmap

Only `docs/canon/ROADMAP.md` + Linear issues linked to it.  
Delete or supersede competing “mission” narratives in chat.

## 4. Naming

- Program name: **PMPS Foundations**  
- Drive root: **PMPS Foundations Controlled Workspace**  
- Git doctrine: **pmps-docs/docs/canon**  
- Design: **pmps-design-system**  
- Do not invent “Foundations 2”, “Control Room v7”, “OS Doc Core” without a CANON PR  

## 5. Agent behaviour (Hermes and others)

1. Open CANON.md first for Foundations tasks.  
2. Never mark blocked gates green without live proof.  
3. Never create a parallel Drive tree or Notion DB “because it’s cleaner” — propose a CANON PR instead.  
4. Separate labels: configured / connected / callable / blocked / unverified.  

## 6. When someone pastes a new mega-plan

1. Diff against CANON + ROADMAP.  
2. Absorb unique good ideas via PR.  
3. Add the paste to SUPERSEDED-INDEX.  
4. Do not run both plans.

## 7. Quarterly

- Re-read CANON in a 20-minute Ashley+Eli meeting  
- Spot-check 10 Register rows vs Drive vs Notion  
- Archive abandoned Linear issues
